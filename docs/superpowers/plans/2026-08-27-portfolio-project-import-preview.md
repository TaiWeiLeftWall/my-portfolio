# Portfolio Project Import Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an offline scanner that inventories the complete photography archive, recommends at most 12 candidate images per project, produces an editable manifest and local preview, and safely refreshes `概览.md` without uploading or publishing anything.

**Architecture:** A small Python package under `upload-tool/project_import/` separates directory discovery, image analysis, deterministic selection, report generation, and overview merging. The command-line entry point composes those units, writes all generated artifacts atomically, and only replaces the authorized overview after every required preview artifact and backup have succeeded.

**Tech Stack:** Python 3.9, Pillow 11.3.0, standard-library `unittest`, HTML/CSS generated by Python, JSON, pathlib, concurrent futures.

**Spec:** `docs/superpowers/specs/2026-08-27-portfolio-project-import-preview-design.md`

## Global Constraints

- Preview mode performs no network requests and does not read R2 credentials.
- The source tree is read-only except for the explicitly authorized atomic replacement of `<source>/概览.md`.
- Every generated project has `publish: false` and `cover: null`.
- Candidate selection is deterministic and returns no more than 12 images by default.
- `.nef`, `.cr3`, `.dng`, `.psd`, archives, spreadsheets, Markdown, hidden files, and temporary files are never candidate images.
- Directory symlinks are not followed.
- Worker count is bounded to the inclusive range 1–8 and defaults to 4.
- Existing unrelated worktree changes remain unstaged and unmodified.
- Generated preview artifacts are written to a user-supplied output directory, not committed to Git.

resolution = min(1.0, (width * height) / 12_000_000.0)
sharpness_score = min(1.0, edge_variance / 1200.0)
